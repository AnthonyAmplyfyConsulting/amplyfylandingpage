# Verification — 2026-11-16

## Automated checks

26 passing tests against the production browser-target Worker bundle and real in-process SQLite:

- 500 simultaneous independent visitor flows, each with a unique round/session and different numbers of safe reveals. Re-read and verified every visitor's own ID, score, claimed amount and absence of hidden mine/secret data.
- 100 concurrent visitors sharing one IP address, each playing and claiming independently.
- Forged credentials combining one visitor's ID with another visitor's secret rejected for reads, reveals, claims and pass downloads.
- Thirty racing reveal/claim calls; stale writes rejected and a retried claim froze a consistent amount.
- Legacy R2 round migration preserved earned state without re-importing stale data.
- Atomic rate limits, oversized streamed bodies, invalid JSON, origin checks, owner-only admin access and security response headers.
- P12 validation, encrypted vault integrity, detached CMS signature/manifest verification, correct reward metadata and pass cache reuse.
- Randomized boards, mine preservation of baseline reward and exactly $500 on fourteen safe tiles.

The 500-visitor local run completed in approximately five seconds on the test machine. This is **not** an HTTP latency, production throughput, Google booking or first-pass Wallet capacity benchmark.

`npm audit --omit=dev` reported zero known production dependency vulnerabilities at the time of this check. That is not a guarantee against undiscovered vulnerabilities.

## Hosted verification

A bounded hosted concurrency check is performed after the D1 migration deployment; its measured results are recorded separately below. No real Google bookings or email invitations are generated by the test.

Hosted check: **30 simultaneous visitors, 120 API requests, 30 unique rounds, zero errors**. Every round was revealed, claimed with a forged client amount (ignored), and re-read with its own browser cookie. The run completed in 22.87 seconds. Client-observed request p50 was 4,669 ms and p95 was 9,157 ms through the private Sites gateway and test network; this is not an acceptable basis for claiming subsecond end-user response times. A separate sample of Worker execution logs distinguishes backend execution from that full network path. First-time Wallet signing and Google booking capacity were not load-tested.

Of the retained execution-log sample, 64 load-test requests were identifiable by their test client and all returned HTTP 200. Worker wall-time p50 was 211 ms and p95 was 420 ms. These sampled Worker timings exclude the private gateway and network; they do not replace the full client timings above.
